Iron Vale · visual identity · option E

THE DETAIL PASS

Same chrome. Same layout. Nothing moves house. What changes is that every piece of it looks like somebody put it there on purpose.

Thirteen touches, ranked by charm per line at the end. Each one shows what it replaces, what it costs, and the sprite data or CSS to transcribe. Every demo below is live — click things.

“the black and gold makes for a clean border, but I feel like it looks just very… AI… even for the ‘send ravens’ button, maybe there’s a little raven you click on… things like that where someone looking might think ‘this was designed with intentionality, not simply to fill a space’.”
every detail here also has to survive prefers-reduced-motion: reduce, which the app already honours app-wide (style.css:2861). Press this to see what a player with that setting gets.

The phone gets it for free. The rule that hides the row is .footer-btns, not .footer — and the bird is not in that row. It grips the footer's own border-top, which is drawn on every viewport. Hide the keys exactly as style.css:2674 already does (the SETTINGS key — on this width there are none left to hide — and the raven simply stays, with a 60×52 tap target from a transparent ::after — comfortably over the 44px minimum the phone contract enforces (style.css:2699). No media query, no :has(), no exception. That is the whole fix.

the five states, and the copy that stands beside each

The failure state has no red in it. Today a lost flight paints ravens delayed since… in --red (style.css:957) — an alarm colour, in a game, for a thing the player cannot fix by hurrying. The bird instead comes back late with its head down and one primary out of place. The copy stays plain --dim-readable. Nothing is broken; a bird had a bad night.

▸ the sprite sheet, and how the flight is wired
16×14 frame box on every frame — the bird can swap frames without the footer shifting a pixel. 8× magnification, 1px grid. palette: k body #26263a · K underside #20202a (the canon body colour) · n rim #4e4e6a · b wing flash #4a5a7a · B wing lit #7186ae · y beak #e0c060 · w eye #d8d0c0

The flier is pinned at page level. G.syncNow() ends in a render() that wipes the DOM — the same problem .key-pop-ghost already solves by appending the ghost to <body> and positioning it over the key (style.css:198-203, app.js). The departing raven does exactly that: position:fixed, z-index:951, seeded from the perch's getBoundingClientRect(), ticked by a frame table on a setInterval. No CSS transition anywhere; every frame is a redraw.

13
    One moth at the vignette edge

  

    pure noise risk
    dies entirely under reduced motion
    2 sprite frames
  

  
Replaces nothing. It is idle life: a moth that drifts in from the dark
  edge toward whatever is brightest on screen. This is the one on the list I would cut first, and
  I have ranked it last on purpose — it is the detail that is only motion, so under
  prefers-reduced-motion it does not degrade, it simply is not there. A detail that
  cannot exist for some players is a detail that cannot carry meaning.

◆
    Do these first

  
Ranked by charm per line — how much of the “somebody made
  this” feeling you buy for each unit of code and each unit of risk.

  
    
    
  1. Corner nails on .win. Three 4×4 sprites and one CSS rule,
    and every panel in the game stops being a rectangle. Nothing to animate, nothing to break,
    nothing to degrade. Highest ratio on the page by a distance — do it in an afternoon
    and see how far it gets you before doing anything else.
    2. 
    
  2. The raven on the rail. The most work here and the only one that also fixes
    a defect: phones currently have no SEND RAVENS control at all. Ravens are the game's oldest
    metaphor and until now there is no raven drawn anywhere in the repo. Ship the perch, the
    blink and the flight; the five states can land in a second pass.
    3. 
    
  3. The title strap. One CSS rule, one margin bump. Pairs with the nails —
    they are the same idea, applied to the two shapes that repeat most.
    4. 
    
  4. The bell. Removes two words of settings vocabulary from the chrome and
    replaces them with an object. One control, four frames, and the key underneath is
    untouched.
    5. 
    
  5. The flame's missing frames. Three sprites, and it retires the last piece of
    tweened sub-pixel motion in an app that is otherwise all hard steps. Frame 1 is already in
    pixel.js, so this is additive.
    6. 
  

  
Then, if the first five land well: the toast
  scrap (06) and the notched scrollbar (09), both contained and both cheap. Hold back:
  the seal (07) until it is gated to danger: true only; the empty states (10) until
  somebody writes the lines, because a drawn empty with a bad line is worse than a good line
  alone. Cut unless you fall in love with it: the moth (13).










  
◆
    What this changes, keeps, and costs

  

    
Changes
      
    
        
  • The SEND RAVENS key becomes a bird, and gets a home on a phone for the first time.
    • 
        
  • The SOUND: ON key becomes a bell.
    • 
        
  • .win gains four nails; .win-title gains a strap and two pegs.
    • 
        
  • Toasts stop sharing a surface treatment with dropdowns and speech bubbles.
    • 
        
  • The failure state stops being red and becomes a tired bird.
    • 
        
  • The last tweened animation in the app is retired for hard frames.
    • 
      

    

    
Keeps
      
    
        
  • Every layout. No screen is restructured, no element moves house, no grid changes.
    • 
        
  • Every token. Nothing here introduces a colour outside the palette except the
        raven's own body values, which are its subject.
    • 
        
  • The key. Face, three bevels, 4px travel, inverted pressed state, the
        .key-pop-ghost flash — all untouched. The bell and the seal sit
        inside keys.
    • 
        
  • The motion vocabulary. Every frame here is a redraw on steps(1, end).
        No easing, no blur, no sub-pixel transform anywhere.
    • 
        
  • The fonts, at their native sizes. No strike is rendered away from its size.
    • 
      

    

    
Costs
      
    
        
  • ~40 new sprite frames in pixel.js, all in the existing
        {p, r} format — roughly 250 lines, no new renderer.
    • 
        
  • A frame-ticker. Nothing in the app currently swaps sprite frames on a clock;
        the raven, flame, bell and seal all need one small shared helper (~20 lines) plus a
        teardown on render(), or timers leak on every navigation.
    • 
        
  • One margin bump on .win for the taller title strap.
    • 
        
  • A ?v=N bump, as every static change requires.
    • 
      

    

    
Where it becomes noise
      
    
        
  • Nails at density. Six stacked Hall panels is 24 nails. Gate to top-level
        .win only — not .tight, not inside .overlay,
        not the nested Council surfaces.
    • 
        
  • The seal on cheap confirms. Gate to danger: true. A seal on
        “discard draft?” devalues the one on “strike from the record”.
    • 
        
  • Idle life generally. One moth is charm; a moth and dust and a spider is a
        screensaver. The Menagerie is already a live simulation — ambient motion must never
        run on a screen that has its own.
    • 
        
  • The ruffled raven. It only means something if it is rare. If sync is chronically
        late for a player, the bird is permanently ruffled and the state stops reading as a state.
        Gate it to genuinely overdue, not merely “more than 15 minutes”.
    • 
      

    

    
Reduced motion
      
    
        
  • The app-wide rule does not save you. style.css:2861 sets
        animation-duration: 0.01ms !important, which kills CSS steps()
        — but every detail here is drawn by a JS timer, and a JS timer does not read a media
        query. Each ticker must check matchMedia('(prefers-reduced-motion: reduce)')
        itself. This is the single easiest thing to get wrong in the whole pass.
    • 
        
  • Degrades cleanly: the raven (flight collapses to gone → returned; every
        state still has its own still frame), the flame (frame 1 = today's sprite exactly), the
        bell (still / muffled), the seal (whole → broken), the candle (a state, not motion —
        untouched), the quill (holds one frame), the toast (never moved anyway).
    • 
        
  • Does not degrade: the moth. It is only motion. Do not ship it behind a
        media query and call that graceful — it means some players simply never have it.
    • 
      

    

    
Surprises found
      
    
        
  • Phones have no way to send ravens. .footer-btns { display: none }
        at style.css:2674 hides the whole row, so the only path is Settings → APIs →
        SAVE & SEND RAVENS (misc.js:942) — which also rewrites the athlete credentials.
        The status line still promises a flight the player cannot order.
    • 
        
  • There is no raven sprite in this repo. Ravens are ~six strings of copy across
        app.js, town.js, giver.js, misc.js and the backend. The bird on this page is built from
        a 9×10 sprite decoded out of a screenshot on a sibling branch, which is the only
        raven the project has ever drawn.
    • 
        
  • quanta-strike-18 and -20 ship and are unwired.
        Two woff2 files nobody loads. Not this pass's business, but worth someone's.
